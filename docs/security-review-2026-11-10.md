# 블로그 보안 점검 · 2026-11-10

## 범위와 결과

현재 저장소의 패키지 잠금 파일, Notion 공개 글 조회, Markdown 렌더링, 글 주소, RSS/XML, 외부 링크, 이미지 설정, portfolio 프록시, 응답 헤더와 추적 중인 파일의 비밀정보 패턴을 점검했다. 운영 서비스에 공격 요청을 보내거나 배포하지 않았다.

npm audit 기준 취약한 의존성 항목은 **17개(critical 1, high 8, moderate 8) → 0개**다. 이 수치는 전이 의존성 중복을 포함한 패키지 항목 수이며, 서로 다른 취약점 수나 실제 침해 건수가 아니다. 알려진 권고에 대한 검사이며 전체 안전성을 보증하지 않는다.

## 수정한 사항

### 1. 알려진 취약점이 있는 패키지

- Next.js / eslint-config-next: 16.2.9 → 16.4.6
- React / React DOM: 19.2.7 → 19.3.1
- PostCSS: 8.5.32로 보안 하한 상향
- sharp: 0.35.5로 갱신
- 검사 도구와 다른 전이 의존성도 호환 범위에서 갱신했다.
- typescript-estree가 사용하는 minimatch에는 11.0.1 이상의 수정 버전을 한정 적용했다. 기존 minimatch 3.x를 사용하는 다른 도구에는 주요 버전 변경을 강제하지 않았다. 이 예외는 상위 패키지가 수정 버전을 채택하면 제거할 수 있다.

Next.js 이미지 처리의 심각 등급 권고는 플랫폼과 입력 조건이 있는 취약점이다. 본 환경에서 원격 코드 실행을 재현한 것은 아니다. 설치 버전의 영향 범위와 수정 버전은 공식 권고 및 npm audit으로 대조했다.

참고: [Next.js 이미지 최적화 권고](https://github.com/vercel/next.js/security/advisories/GHSA-2464-fhr4-w9xw), [Next.js 보안 공지](https://github.com/vercel/next.js/security/advisories), [minimatch 권고](https://github.com/advisories/GHSA-g3hv-75wg-m249)

### 2. 공개 상태 판정의 기본 허용 문제

기존에는 정확히 private인 상태만 비공개로 처리했다. 빈 값, draft, 오타 등도 공개로 처리되는 경로를 코드로 확인했다.

이제 status/visibility 값이 **public**인 경우에만 게시한다(대소문자와 앞뒤 공백 허용). 나머지는 비공개이며 본문 요청 전에 제외한다. 이전 정책으로 생성된 데이터 캐시를 재사용하지 않도록 캐시 키도 변경했다. 회귀 테스트에서 비공개·초안·빈 상태의 본문을 조회하지 않고 목록과 상세 조회에서 제외함을 검증했다.

운영 시 게시할 글의 상태는 반드시 public으로 지정해야 한다. 이미 공개된 글의 비공개 전환은 기존 페이지/데이터 캐시 갱신 정책에 영향을 받는다. 이 수정은 즉시 게시 취소 기능을 추가하지 않는다(기본 재검증 간격 15분).

### 3. 글 주소와 RSS XML 입력 처리

Notion slug를 검증 없이 경로와 XML 문자열에 삽입하던 부분을 수정했다. 글 주소는 문자·숫자·하이픈·밑줄로 이루어진 단일 경로 조각만 허용하며, 잘못된 값은 페이지 ID를 사용한다. 기존에 특수문자·점·슬래시를 쓴 slug는 주소가 변경될 수 있다.

RSS의 URL 텍스트와 속성까지 XML 이스케이프를 적용하고 금지된 제어문자를 제거했다. RSS와 사이트맵의 글 주소도 URL 인코딩한다. 악의적인 XML 구분자, 경로 탈출, 쿼리·fragment·스킴 삽입 사례를 회귀 테스트로 확인했다.

### 4. 응답 헤더 보강

블로그 경로에 nosniff, SAMEORIGIN, referrer 정책과 CSP의 base-uri/object-src/frame-ancestors 제한을 추가했다. 프레임 삽입과 base 태그·객체 삽입을 제한하는 부분 CSP이며, 스크립트까지 제어하는 전체 XSS 방어 정책은 아니다. Next.js 버전 식별 헤더도 제거했다.

## 그 외 확인 사항 및 유지한 항목

- Markdown은 React 노드로 렌더링하며 임의 HTML 실행 경로가 없다. 링크·본문 이미지는 HTTP(S) 패턴을 사용한다. 테마 초기화의 인라인 스크립트는 외부 입력을 삽입하지 않는 고정 문자열이다.
- Notion 토큰은 서버 환경변수에서만 읽는다. 현재 추적 파일에서 검사한 토큰·개인키 패턴은 발견하지 못했고 .env 파일도 추적되지 않는다. Git 전체 이력, 배포 설정, 실제 비밀정보 저장소는 검사하지 않았다.
- portfolio 프록시는 고정된 상위 호스트를 사용하며 요청자가 목적지 호스트를 지정하는 구조가 아니다. `/` 연결을 유지했다. portfolio 저장소 자체는 이번 점검 범위에 포함하지 않았다.
- @notionhq/client 2.3.0은 최신 5.x보다 오래되었지만 이번 audit에서 알려진 취약점은 보고되지 않았다. 기존 databases API를 사용하므로 데이터 소스 모델 변경과 실제 Notion 연결 검증이 필요한 주요 버전 전환은 적용하지 않았다. [Notion 마이그레이션 안내](https://developers.notion.com/guides/get-started/upgrade-guide-2025-09-03)
- ESLint는 플러그인 호환성을 위해 9.39.5를 유지했다. 알려진 취약점은 0건이지만 지원 종료 경고가 있으므로 향후 플러그인과 함께 10.x로 이전해야 한다. 10.x를 시험했으나 플러그인 peer 의존성 경고 및 다른 minimatch 취약점이 발생해 적용하지 않았다.
- TypeScript 7.x와 Node 타입 26.x로의 주요 버전 전환은 보안 패치와 별개인 마이그레이션으로 남겼다.

## 검증

- npm audit: 전체 의존성에서 0건
- npm run test:security: 4개 테스트 통과(공개 판정, slug, XML, 모의 Notion 조회 파이프라인)
- npm run lint: 통과
- npm run build: Next.js 16.4.6으로 통과
- 실제 로컬 HTTP 응답: `/`, `/blog`, `/blog/articles`, RSS, 사이트맵, 프로필 이미지 모두 200
- 블로그 응답의 보안 헤더·버전 헤더 제거를 검증하고 RSS/사이트맵을 XML 파서로 검사

실제 Notion 자격증명이 없는 환경이므로 운영 데이터와의 연결 및 상태 값은 검증하지 못했다. 공개 상태 로직은 모의 API 응답으로 검증했다. 변경 사항은 로컬에 있으며 보안 패치의 운영 반영에는 새 빌드 배포가 필요하다.
